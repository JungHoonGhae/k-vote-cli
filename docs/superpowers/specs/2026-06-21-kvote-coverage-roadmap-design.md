# kvote 데이터 커버리지 로드맵 + Phase 1 설계

작성일: 2026-06-21
상태: 승인됨 (P1 구현 착수)

## 1. 취지 (Mission)

최근 선거관리위원회의 투명성·관리 행태에 대한 사회적 의구심이 커지면서, **공개된 선거
데이터에 누구나 쉽게 접근해 스스로 확인할 수 있는 인프라**의 필요가 분명해졌다. 기존에는
이 데이터가 robots 차단·JSF 포털·PDF·복잡한 클릭 흐름 뒤에 흩어져 있어 사실상 일반
시민·연구자·AI 에이전트가 접근하기 어려웠다.

`kvote` 의 목적은 단 하나 — **그 접근성을 최대한 끌어올리는 것.** 흩어진 공개 데이터를
키 없이 한 번의 명령으로, 구조화된 형태(JSON/JSONL)로, AI 에이전트가 그대로 질의할 수
있게 만든다.

### 1.1 중립성 원칙 (Non-negotiable)

**kvote 는 어떤 분석적 입장도 취하지 않는다.** 우리의 역할은 데이터 접근성을 높이는 것
뿐이며, 무엇이 정상·비정상·수상한지 판단하지 않는다.

- **제공한다**: 분석에 필요한 파라미터와 차원을 광범위하고 중립적으로. 원자료를 빠짐없이
  보존하고, 정의가 명확한 표준 파생값(비율·합계·집계)을 함께 제공한다.
- **하지 않는다**: 플래그·점수·순위·"이상치"·"검증 결과"·해석. 어떤 값이 문제인지의
  판단은 전적으로 소비자(사람 또는 AI 에이전트)의 몫이다.
- **설계 제약**: 모든 파생 필드는 *정의가 명시된, 재현 가능한 표준 변환*이어야 한다.
  "수상함"을 내장한 휴리스틱은 들어가지 않는다.

이 원칙은 README·CLAUDE.md 최상단에도 명시한다.

## 2. 로드맵 (검증 가치순, 단계적)

여기서 "검증 가치"란 *최근 쟁점을 소비자가 스스로 확인할 수 있도록, 우리가 가진/얻을 수
있는 데이터로 얼마나 풍부한 중립 파라미터를 제공하는가* 를 뜻한다. 우리가 검증하는 것이
아니라, 소비자의 검증을 가능케 하는 정도다.

| Phase | 내용 | 근거 |
|---|---|---|
| **P1** 🔴 | 개표 분석 파라미터 광범위 제공 (투표유형 분리·다단계 집계·득표율·투표율) | 가장 큰 쟁점(사전/본 격차)을 *이미 가진 데이터*로 슬라이스 가능하게 |
| **P2** 🟠 | 개표 완전 커버리지 — XLSX(지방선거 등) → CSV와 동일 스키마 수렴 | 모든 선거종류를 같은 도구로 |
| **P3** 🟡 | 투표율(turnout) 데이터셋 정규화 | 독립적 파라미터 축 |
| **P4** 🟡 | 여론조사 교차표(이념·연령·지역) 파라미터화 | 여론조사↔개표 비교를 소비자가 가능하게 |
| **P5** 🟢 | 통합 로컬 데이터셋(SQLite) + AI 에이전트 질의 인터페이스(MCP) | 누구나/AI가 교차·집계 질의 — 분석은 소비자가 |

각 Phase 는 독립된 spec→plan→구현 사이클을 가진다. 본 문서는 P1 을 상세화한다.

## 3. Phase 1 상세 설계 — 개표 분석 파라미터 (중립)

### 3.1 목표

이미 `nec results` 가 정규화하는 투표구 단위 `ResultRecord` 위에, **분석에 필요한 중립
차원·파라미터를 더한다.** 새 데이터 수집 없이, 가진 데이터를 더 풍부하게 슬라이스할 수
있게 만드는 것이 핵심이다. 우리는 어떤 결론도 내지 않는다.

### 3.2 추가 차원·파라미터

1. **투표유형(VoteType) 차원** — 각 투표구가 어떤 유형인지 데이터 구조에서 그대로 도출:
   - `거소·선상투표` (town 이 "거소·선상투표") → `거소선상`
   - `관외사전투표` (town 이 "관외사전투표") → `관외사전`
   - booth 가 "관내사전투표" → `관내사전`
   - 그 외 (실제 읍면동 + 투표구) → `본투표`

   이는 판단이 아니라 데이터가 이미 말하는 구조 라벨이다. `ResultRecord.VoteType` 필드 추가.

2. **다단계 집계(Aggregation)** — 투표구 레코드를 상위 단위로 합산:
   - 레벨: `town`(읍면동) · `sgg`(선거구) · `sido`(시도) · `national`(전국)
   - 후보 합산은 *후보가 동일한 범위*에서만 의미가 있으므로 **선거구(sgg) 이하에서만**
     후보별 합계를 낸다. 시도·전국 집계는 지역구 후보가 서로 다르므로 **지표(선거인수·
     투표수·무효·기권·투표율)만** 합산하고 후보 목록은 비운다. (이 한계를 출력·문서에 명시.)
   - `--by-votetype` 옵션: (집계단위 × 투표유형)으로 분리 → 소비자가 사전/본 득표율을
     같은 단위에서 나란히 비교할 수 있다. (비교·판단은 소비자가 한다.)

3. **표준 파생 파라미터 (정의 명시)** — 모두 재현 가능한 산술:
   - `유효투표수` = 투표수 − 무효투표수
   - `투표율(turnout)` = 투표수 / 선거인수
   - 후보별 `득표율(share)` = 후보득표 / 유효투표수  *(정의를 필드 주석·문서에 명시;
     원자료가 모두 보존되므로 소비자는 투표수 기준 등 다른 정의로도 직접 계산 가능)*
   - 원자료(선거인수·투표수·무효·기권·후보별 득표)는 **항상 그대로 보존**한다.

### 3.3 컴포넌트 (internal/nec)

- `results.go` (기존): `ResultRecord` 에 `VoteType` 추가, 파싱 시 분류.
- `aggregate.go` (신규):
  - `type AggregatedRecord struct { Level, Sido, District, Town, VoteType string;
    Electorate, Votes, Invalid, ValidVotes, Abstention int; Turnout float64;
    Candidates []CandidateShare }`
  - `type CandidateShare struct { Party, Name string; Votes int; Share float64 }`
  - `func Aggregate(recs []ResultRecord, level AggLevel, byVoteType bool) []AggregatedRecord`
  - 순수 함수(네트워크 무관). 그룹 키 구성 → 합산 → 파생값 계산.

### 3.4 CLI (cmd/kvote/nec.go)

`nec results` 에 플래그 추가 (별도 명령 없음 — 같은 데이터의 뷰):

```
nec results <pk> [--file PATH]
  --aggregate {none|town|sgg|sido|national}   기본 none(투표구 원단위)
  --by-votetype                               투표유형으로 분리 (집계와 함께)
  -f json|jsonl|table
```

- `none`: 기존 동작(투표구별 `ResultRecord`, 단 `voteType` 필드 추가).
- 집계 시: `AggregatedRecord` 출력. table 은 핵심 열(단위·투표유형·선거인수·투표수·투표율·
  후보수), 후보 상세는 json/jsonl.

### 3.5 에러 처리

- 집계는 파싱된 레코드 위에서 동작 → XLSX 등 파싱 불가 데이터셋은 기존 `nec results` 와
  동일한 "레이아웃 불일치" 에러(향후 P2). `nec pull` 로 원본 안내.
- `--by-votetype` 는 집계에만 영향. `--aggregate none` 과 함께 주면 원단위 레코드에
  `voteType` 이 이미 포함돼 있으므로 **무해한 no-op**(추가 분리 없음). 별도 에러 없음.
- 선거인수 0 인 단위의 투표율: 0 으로 두고 분모 0 은 계산하지 않음(NaN 방지).

### 3.6 테스트 (internal/nec/nec_test.go)

- `TestVoteTypeClassification`: 4유형(본/관내사전/관외사전/거소선상) 분류.
- `TestAggregateSgg`: 작은 픽스처 → 선거구 합산 지표·후보합·득표율·투표율 정확.
- `TestAggregateByVoteType`: (선거구 × 투표유형) 분리, 사전/본 그룹이 각각 합산.
- `TestAggregateSidoDropsCandidates`: 시도 집계 시 지표만, 후보 비움.
- 모두 네트워크 없이 순수 함수 검증.

### 3.7 비범위 (Out of scope — 중립성)

- ❌ `verify`/플래그/이상치/점수/순위/해석 — 일절 없음.
- ❌ 사전·본 "격차" 자체를 우리가 계산해 강조하지 않음. 소비자가 같은 단위로 나란히 받아
  직접 비교한다. 우리는 분리해 제공만 한다.
